01 · foundations

Principles

Five decisions made up front; every rule below follows from one of these.

HIG quality bar, not a costume

We take Apple's discipline — hierarchy through type, rhythm through spacing, motion that explains, restraint everywhere. We skip the acting: no liquid glass, no fake iOS, no shadows pretending. It's a web app and it's honest about it.

The transcript is the product

iMessage metaphor for messages: bubbles carry the chat, chrome recedes. The agent's work folds away; the answer is the only thing claiming visual weight.

One accent, meaning never adjacent to decoration

Brand blue #293352 is the only interactive color. Status colors (ok, error, warn) talk about processes only — never about things you can press. Orange is gone.

One motion vocabulary

A single easing curve and two durations for the entire app. Motion plays only on state change; hover gets an instant color shift; streamed text glides, never jitters.

Performance is a design constraint

System fonts, inline SVG, transform/opacity animation only, append-only transcript, rAF-smoothed scroll. Nothing here costs a frame or a kilobyte of font.

02 · foundation

Color

HIG: "avoid using the same color to mean different things." The palette is one navy family plus three re-tinted semantic hues. Semantic values are Apple's hues pulled toward the brand's ~220° coolness; every value has a dark variant — dark values are not inversions, they're re-lifted (HIG dark-mode rule).

Rules
  • Brand blue never styles static text. If it doesn't do something when you click it, it isn't blue.
  • Green/red/amber never style anything interactive. If you can press it, it's chrome, not a status.
  • Color is never the only signal — every state also has text (HIG inclusive-color rule). "failed" is the word red accompanies, not replaces.
  • Body text contrast ≥ 4.5:1 everywhere; we aim at HIG's 7:1 for the small sizes (11–12px).

03 · foundation

Typography

System font stack (SF on every Apple device you demo this on, native look on others) — zero payload, HIG's own choice. The hierarchy is a fixed ramp that mirrors iOS text styles: a size belongs to a role, and roles don't ad-lib sizes. HIG minimums respected (iOS min 11pt; body at 15 for chat readability).

Depth rules
  • Flat surfaces separate by hairline --border, never stacked shadows. In dark mode separation comes from layering: base #131519, elevated #1f232a, panels #1a1d22.
  • Elevation only for floating elements: ↓ latest button, mobile drawer + scrim. Nothing else casts a shadow.
  • Bubbles are uniform 16px radius — no asymmetric iMessage tails. The chat metaphor lives in placement and grouping, not in shape cosplay.
05 · foundation

Icons

Lucide, adopted open library — SF Symbols' stroke style, MIT, tree-shaken inline SVG so the palette tokens color them for free. icon color = currentColor always; stroke 2 at 16px, 1.5 at 20px+; icons always carry a label or an accessible name (they accelerate, they don't riddle). Escape hatch: any icon can later be swapped for a hand-drawn one without touching the system.

06 · foundation

Motion

HIG: motion supports the experience, never overshadows it; frequent interactions get no added motion; people can always cancel it. Level-2 commitment: a single easing vocabulary + choreographed state transitions + silky stream follow. prefers-reduced-motion collapses every animation on this page — that's a feature, not a bug (it's how the shipping app behaves under the setting).

›
The spine, in order: window — while the model works, its text lives in a fixed masked window (above) and translates smoothly through it, DeepSeek-style; when work settles it collapses to a thought for … row that expands. reveal — every token chunk fades in (~150ms opacity + 1.5px blur) on arrival; no cursor — the pill's breathing dot already says “running”. scroll — scrollTop lerps toward the bottom in a rAF loop (~75ms time constant), never jumps; a chunk landing elsewhere never steals the viewport — scroll up and the follow stops, the jump pill appears (spinner while running, plain when idle) and glides you back. The reveal rate needs no syncing logic: fade duration < median inter-token interval, so visibility simply follows tps.

10 · shipping

Implementation

Ordered so each step improves the app on its own; no step is a rewrite.

  • 1
    Tokens + dark mode. Replace the :root block in style.css with the token sheet from the top of this file (plus the @media (prefers-color-scheme: dark) mirror). color-scheme follows the OS; no toggle in the app.
  • 2
    Ramp sweep. Every font-size snaps to a token; transcript body 14.5→15, chrome 13, steps stay 12 mono, captions 11 caps.
  • 3
    Accent migration. All #ff6b35 uses → var(--accent); error → --error (pink-red pair); stop button loses its warm tint, becomes a danger pill (icon + label). Status pill component arrives here.
  • 4
    Motion tokens. All keyframes adopt --ease + the two durations. Spin/pulse keep their periods but breathe on the shared curve. No cursor anywhere — running state lives in the status pill's breathing dot.
  • 5
    Generation spine, A — scroll. rAF lerp on #transcript.scrollTop in main.ts, exponential glide (≈75ms time constant). Auto-follow only when the reader is at the bottom; otherwise the floating ↓ latest pill shows (spinner inside while generating, plain when idle) and jumps with the same glide. Testable alone.
  • 6
    Generation spine, B — reveal. Each streamed token chunk is wrapped and faded in on arrival (~150ms opacity + 1.5px blur; fade shorter than the median inter-token interval, so perceived pace tracks tps with no syncing logic). No new dependency — this is what smoothStream() does server-side, done where it belongs (see “Streaming” note below).
  • 7
    Generation spine, C — live window. While the model works, thinking/tool text lives in a fixed ~3-line masked window whose content translates smoothly through it (DeepSeek-style); on settle it collapses to a thought for X s › row that expands on tap. Tool rows: call text truncated one line, status dot (green landed / red failed / spinner running), full call + result unfold on tap; reasoning as a quiet italic collapsible that auto-collapses at turn end.
  • 8
    Lucide inline. 8 icons in a TS module (plain svgPath strings), stroke inherits currentColor. Send/menu/refresh/new/latest/compact get icon buttons at 44px zones; stop keeps a word.
  • 9
    Mobile drawer. Below 800px: top bar identity row + drawer sheet with scrim, reusing the level-2 easing; existing resize/localStorage logic stays desktop-only.
  • 10
    Radii + spacing sweep. Ad-hoc radii → the 6/12/16/999 scale; paddings snapped to the 4px grid.

    • Accepted tradeoffs, in one line each: no manual theme toggle in the app (OS-follow is the behavior, revisit when there's a settings screen); open Lucide icons may feel generic (swap any for hand-drawn strokes when it itches); bubbles are uniform-radius, so no iMessage tail cosplay.

    Streaming — where the smoothing lives
    • We don't own a streamText() layer, so AI SDK's smoothStream() isn't directly applicable; the bridge could re-emit on a fixed timer, but a fixed delay masks real tps changes (lag pile-up on bursts, dead air on pauses).
    • Chosen: do it client-side, where the pixels are — keep a small pending buffer in main.ts, drain on each requestAnimationFrame with the fade above; a backlog after a burst simply resolves over the next frames, visible pace always equals the model's real pace. ~30 lines, no dependency.
    • A React token-animation lib (FlowToken et al.) is the same idea with a React tax we don't pay. If we ever port the client to React + AI SDK, smoothStream() becomes viable behind identical pixels.
